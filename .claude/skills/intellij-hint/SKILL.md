# 힌트에 IntelliJ 팁 곁들이기

사용자는 IntelliJ IDEA(macOS 기본 키맵)에서 미션 코드를 **직접** 친다.
힌트에 나온 바로 그 코드를 더 빨리, 오타 없이 치는 방법을 그때그때 알려 주면, 강의 개념과 함께 도구도 손에 익는다.
단, 도구가 학습을 대신하면 안 된다. 이 저장소의 목적은 사용자가 개념을 직접 써 보는 것이기 때문이다. (CLAUDE.md "진행 방식" 참고)

## 언제 쓰나

- 미션 힌트의 모든 단계: 힌트 → 부분 코드 → 전체 코드
- "OO 확인해줘"나 리뷰에서 고칠 곳을 안내할 때. 특히 IDE 기능이 딱 맞는 경우가 그렇다: 정렬은 `Cmd+Option+L`, import 정리는 `Ctrl+Option+O`, 이름 일괄 변경은 `Shift+F6`, 빨간 줄은 `Option+Enter`
- 사용자가 IntelliJ 사용법이나 단축키를 직접 물을 때

컴파일 에러를 설명할 때는 `F2`(다음 에러로)와 `Cmd+F1`(에러 설명)이 잘 맞는다.

## 팁 고르는 법

1. **사용자가 이번에 칠 코드를 본다.** 힌트에 나온 메서드 뼈대, 반복문, `null` 검사, 출력문, 새로 만들 파일 같은 것이다.
2. **`references/shortcuts.md`에서 그 코드에 직접 쓰이는 것만 2~4개 고른다.** 많이 주면 하나도 안 남는다. "이 코드를 칠 때 바로 누를 수 있는가"가 기준이다.
3. **진도를 확인한다.** README "진행 현황"을 보고, 참고표 2장의 표에서 아직 안 배운 개념을 만들어 내는 기능은 빼거나 "OO을 배우면 쓸 수 있어요" 한 줄로만 남긴다.
   예: final을 배우기 전에는 `psf`를 소개하지 않고, 예외를 배우기 전에는 `try/catch` 감싸기를 소개하지 않는다.
4. **처음 배우는 문법은 손으로 먼저 치게 한다.** 생성 기능은 사용자가 한 번 이상 직접 써 본 코드에만 권한다.
   예: 미션 1에서 getter와 생성자를 손으로 써 봤으니, 미션 2의 `Item`에서는 `Cmd+N`을 권해도 된다.
   이번 미션의 핵심 로직(예: `removeStock` 안의 조건문)은 생성 기능으로 만들 수 없으니, 팁도 그 로직을 대신 써 주는 쪽이 아니라 치는 속도를 돕는 쪽으로 고른다. 포스트픽스 `.not`, `.fori` 같은 것이다.
5. **미션 규칙을 깰 수 있는 생성 기능은 경고를 붙인다.**
   예: 미션 2에서 `Cmd+N → Getter and Setter`로 전체를 선택하면 만들면 안 되는 `setStockQuantity()`가 생긴다. 이럴 땐 "Setter는 `id`만 고르세요"처럼 쓴다.
6. **같은 대화에서 이미 알려 준 팁은 되풀이하지 않는다.** 새 팁을 하나 이상 넣는다. 다시 필요하면 표 없이 한 줄로 짧게 상기시킨다.
7. **처음 알려 줄 때 한 번씩만 붙일 주의 사항이 두 가지 있다.**
   - 약어나 포스트픽스를 처음 알려 줄 때: "영문 입력 상태에서 쳐야 해요."
   - F키 단축키를 처음 알려 줄 때: "맥북은 `fn`을 같이 눌러야 할 수 있어요."

## 형식

힌트 본문을 다 쓴 **뒤에** 아래 섹션을 붙인다. 힌트의 흐름을 끊지 않기 위해서다.

```markdown
### IntelliJ 팁

| 하고 싶은 것 | 이렇게 | 결과 |
|---|---|---|
| (힌트 속 작업) | `키` 또는 `약어` + `Tab` | (생기는 코드나 화면) |
```

- 키는 `Cmd+N`, `Option+Enter`처럼 글자로 쓴다. ⌘⌥ 같은 기호는 쓰지 않는다. 사용자가 기호에 익숙하지 않을 수 있다.
- 약어와 포스트픽스는 "무엇을 치면 무엇이 되는지" 짧은 전후 예시를 하나 붙이면 가장 잘 와닿는다. 힌트 속 실제 변수 이름을 쓴다.
- 대화 말투는 CLAUDE.md대로 한국어 존댓말(해요체)을 쓴다.

### 예시 (미션 2, `Item` 힌트 뒤에 붙인 경우)

```markdown
### IntelliJ 팁

| 하고 싶은 것 | 이렇게 | 결과 |
|---|---|---|
| 생성자 만들기 | 필드를 다 쓴 뒤 `Cmd+N` → Constructor → `name`, `price`, `stockQuantity`만 선택 | `id`를 뺀 생성자 |
| getter 4개 만들기 | `Cmd+N` → Getter → `Cmd+A`로 전체 선택 | `getId()` ~ `getStockQuantity()` |
| `setId`만 만들기 | `Cmd+N` → Setter → **`id`만** 선택 | 재고 setter는 만들지 않기 (이번 미션 규칙) |
| 다 쓰고 정리 | `Cmd+Option+L` | 들여쓰기·띄어쓰기 정렬 |

생성자와 getter는 미션 1에서 손으로 써 봤으니 이제 생성 기능을 써도 좋아요.
`addStock`, `removeStock`, `isSoldOut`은 직접 쳐 보세요.
```

## 정확성

- 단축키는 `references/shortcuts.md`에 있는 것을 쓴다. macOS 기본 키맵 기준이다.
- 표에 없는 것이 꼭 필요하면 확실한 것만 쓰고, "안 되면 `Cmd+Shift+A`에서 '기능 이름'을 검색하세요"를 붙인다. 틀린 단축키를 한 번 알려 주면 사용자는 IDE가 고장 난 줄 안다.
- 사용자가 단축키가 안 된다고 하면 다음 세 가지를 차례로 확인하게 한다.
  1. 한/영 입력 상태
  2. 맥북의 `fn` 키
  3. `Cmd+Shift+A`로 검색해 보이는 실제 단축키 (키맵이 다를 수 있음)
